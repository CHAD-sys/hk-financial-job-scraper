00What this project actually is

One sentence, then the honest complication.

It is a daily-run Python backend that scrapes job postings from Hong Kong's largest financial employers, enriches each one with AI, stores everything in a single SQLite file, and then hands that data to four separate delivery surfaces — a React web app, a read-only PocketBase mirror, PDF intelligence reports, and a daily email.

The project's own CLAUDE.md still describes it as "scraping + enrichment + storage backend only — no web UI." That was true when it was written. The codebase has since grown a full webapp/ (FastAPI + React) on top of the same jobs.db, plus an entire second subsystem (hk_jobs/posts/) that watches LinkedIn recruiter posts through a paid vendor API. Both are real, tested, and running — the docs just haven't caught up. Treat this page, not the CLAUDE.md snapshot, as current.

Backend core python

hk_jobs/ — scrape, enrich, store. Runs headless, once a day, via cron.

Web app react + fastapi

webapp/ — a thin read-only API over the same jobs.db, and the React UI that calls it.

Reports & mirror delivery

scripts/, pocketbase/ — PDFs, email, and a stakeholder-facing PocketBase copy of the data.

01The shape of the system

03Adapters — hk_jobs/adapters/

One file per source type. Every one implements fetch_jobs() -> list[Job] against base.py's BaseAdapter, and every one is wrapped in _safe_fetch() so an exception logs and returns [] instead of killing the run. Tried in this priority order per company.

2eightfold.pyCompany's own Eightfold AI tenantDirect JSON GET, same idea as Workday.
3efc.pyeFinancialCareersFinance-specialist board — first fallback for firms without their own ATS API.

A handful of firms (Goldman Sachs, JPMorgan, DBS) have almost no clean JobsDB presence, so indeed.py is their primary source rather than a fallback — same legal posture, just promoted for those specific employers.

04AI enrichment

One DeepSeek call per job, run in Phase 3, writing into a separate job_enrichments table — the raw scraped row is never overwritten.

What gets added

  • Seniority (intern → executive)
  • Job category, remote type
  • Required skills (structured list)
  • Estimated HKD salary range + confidence
  • description_summary — ≤3 sentences for the job card

Salary calibration

salary_clamp.py's clamp_salary() is the #4 most-connected function in the whole codebase (47 edges) — every estimate gets checked against real anchor tables in salary_guidlines/ (Hays, Adecco, PersolKelly) before it's trusted, so DeepSeek can't hallucinate a HK$2M graduate salary.

Jobs with no description (mainly Indeed listing-only rows) get an empty summary string — never a hallucinated one, per the working agreement in CLAUDE.md.

05Recruiter Posts — hk_jobs/posts/

A second, parallel pipeline, deliberately separate from the adapters above. It surfaces live mandates recruiters post on LinkedIn before they ever reach a job board — the "Secret Market" / Recruiter Posts tab in the UI.

The one deliberate exception to "no paid services"

DIY LinkedIn scraping was evaluated and rejected (authwall, legal risk, anti-bot arms race — see docs/PLAN_LINKEDIN_POSTS.md §3). Instead this subsystem pays a third-party vendor, Apify / HarvestAPI, to do the LinkedIn access — the repo's own code never touches LinkedIn directly here. Hard-capped at $30/month, enforced (not just logged) by budget.py against a running vendor_costs ledger table.

07webapp/backend/ — the FastAPI layer

Deliberately tiny: one file, main.py (777 lines) — no ORM, no auth, PRAGMA query_only=ON enforced at the connection level. It is a read-only window onto jobs.db; nothing here ever writes.

RouteReturns
GET /api/jobsPaginated, filtered, sorted job list. Filters: search, sector, company, seniority, remote type, skills, salary/experience range, tier (boutique/mainstream/social), is_new/urgently_hiring/max_applicants (board-signal filters), hidden_only, verified_only.
GET /api/jobs/{source}/{source_id}Full job detail, including which other boards the same vacancy is listed on.
GET /api/filtersDistinct values + counts for every filterable field, to populate the sidebar.
GET /api/statsAggregate counts by sector/seniority/remote-type/tier, top skills, top companies.
GET /healthLiveness + resolved DB path.

Two things worth understanding in depth

Sector is computed, not stored. There's no sector column — every request classifies each row live via a SQL CASE built from hardcoded company-name term lists (_IB_TERMS, _INS_TERMS, _AM_TERMS, etc. — Investment Banking, Insurance, Asset Management, Professional Services, Digital Assets, else Banking).

Cross-posted jobs share signals. When the same vacancy sits on JobsDB and Indeed, only one copy is shown (is_primary=1), but /api/jobs batch-fetches every hidden copy's board_signals so the single displayed card still shows "urgently hiring" even if that flag only existed on the hidden Indeed copy.

How a filter change becomes a request

JobBoardPage.tsx holds a JobFilters object (defined in client.ts as DEFAULT_FILTERS). Every filter interaction updates that object, which is serialised to the URL query string via filtersToSearchParams() — so a filtered view is always a shareable/bookmarkable link — and deserialised back on load via searchParamsToFilters(). The object is then turned into a FastAPI-compatible query string by fetchJobs() and sent to GET /api/jobs.

The three tabs on the board (All / Exclusive / Recruiter Posts) are just the tier filter: boutique = longtail/LLM-scraped firms, mainstream = the 5 structured adapters, social = promoted Recruiter Posts.

Local design system

webapp/frontend/DESIGN.md documents the app's own visual language, and the frontend has two of its own project-scoped Claude Code skills: .claude/skills/design-audit and .claude/skills/react-doctor (lint/a11y/bundle/architecture triage) — both loaded automatically the moment you touch a file under webapp/frontend/.

09The other delivery surfaces

The web app is one of four things this data feeds. The other three are older and simpler.

PocketBase mirror read-only

pocketbase/ — a self-contained Go binary + pb_migrations/. sync_pocketbase.py pushes active jobs into it daily (Phase 4). Exists for stakeholders who want a browsable admin UI without touching SQLite directly. Non-fatal if it's down.

PDF intelligence reports scripts/

generate_intelligence_report.py, generate_full_report.py, generate_trend_report.py → land in outputs/ and data/. Built on hk_jobs/analytics.py's snapshots.

Daily email notifications.py

Phase 6 of daily_run.sh — summary of the run, plus immediate failure alerts.

CSV export scripts/export_jobs_csv.py

Flat jobs_export.csv at repo root — ad-hoc analysis / handoff format.
